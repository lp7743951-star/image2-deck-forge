# Revision Workflow

## Identify scope

Capture:

- exact slide number or image name;
- current problem;
- requested direction;
- content that must remain;
- new or replacement text;
- whether the image set, PPTX, or full package must be updated.

Ask a short clarification only when the target or desired direction is ambiguous.

## Preserve approved work

- Keep the selected style, full Style Lock, ratio, page role, naming, and output directory.
- Do not regenerate untouched slides.
- Do not silently rewrite approved copy.
- Do not switch styles because one page failed.
- Reuse the approved thumbnail board as continuity evidence when available.

## Rewrite the target prompt

State what remains invariant and what changes. Keep the semantic visual anchor relevant to the page claim. If the visual anchor changes, explain why the replacement is more accurate.

For a text correction, provide exact visible replacement text. For a layout correction, preserve content and specify the new page type or composition.

## Regenerate and review

Generate only the target page image with Image 2. Compare it against adjacent approved slides for palette, grid, typography, containers, headers, footers, and density.

Present the replacement for approval. Do not rebuild the final package before approval.

## Reassemble

After approval:

- replace the ordered image;
- rebuild the image-only PPTX without changing page count or order;
- rebuild the zip;
- append a concise revision record with target, request, changed artifacts, and package status.

Do not add a visible revision date unless the user requests it.
