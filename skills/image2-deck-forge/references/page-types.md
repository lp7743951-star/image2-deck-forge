# Page Types

Choose a page type before writing each prompt. Every page has one core claim.

## Cover

Use for the opening. Include one strong title, one short subtitle, and one visual anchor. Covers may be expressive; they do not set the acceptable density for inner pages.

## Contents

Use for decks with meaningful sections, usually more than six slides. Show 3-6 concise sections. Do not consume an inner-slide section number when the selected style uses numbered headers.

## Section divider

Use to reset rhythm between chapters. Prefer one short statement, a section number, and one semantic symbol or image. It may be image-free.

## Core claim

Use for the deck's main assertion. Give the claim dominant scale and support it with at most three pieces of evidence.

## Comparison

Use for two or three alternatives, states, or time horizons. Keep columns symmetrical unless the message intentionally favors one side.

## Framework

Use for a system, capability model, or set of related concepts. Prefer a 2x2, central concept with satellites, layered stack, or modular grid. Avoid meaningless radial diagrams.

## Process

Use for a sequence, workflow, or operating model. Limit visible steps to 3-6. Show direction and state, not decorative arrows.

## Timeline

Use when chronological order is essential. Verify dates before displaying them. Use milestones and short labels rather than prose.

## Data

Use for metrics, trends, or evidence. Lead with one decisive number or chart. Never invent data, axes, labels, or source notes.

## Case

Use for a concrete example. Organize around context, action, and result, or problem, intervention, and evidence.

## Checklist

Use for actionable criteria. Keep 3-7 short items. Use one repeated marker system.

## Quote

Use when exact words carry authority or emotion. Keep the quote short and source attribution accurate. Do not fabricate quotation marks or speakers.

## Conclusion

Use for the final judgment and next action. Include one decisive statement and up to three actions or memory points.

## Thank-you

Use only when the presentation setting benefits from a formal close. Keep it minimal and do not repeat the entire deck identity.

## Selection rules

- If the page has a sequence, use process or timeline.
- If it has alternatives, use comparison.
- If it explains relationships, use framework.
- If it proves a claim with numbers, use data.
- If it grounds an idea in reality, use case.
- If it asks the audience to do something, use checklist or conclusion.
- If no page type fits, sharpen the claim before inventing a layout.
